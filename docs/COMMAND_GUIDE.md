# COQ 管理员指令教程

适用于 CoreProtectAddon / COQ 1.6.2。本文从实际调查场景介绍 `/coq`，安装和数据库配置见 [README](../README.md#配置)。

COQ 读取 CoreProtect 已保存的日志，提供独立查询、历史物品查看和组件筛选。它不提供回滚、恢复或检查器，也无法查询未记录、尚未写入或已清理的数据。

## 1. 开始前

确认插件数据库初始化完成，并且连接的是需要调查的 CoreProtect 数据。查询权限为 `coreprotectaddon.command.query`，默认 OP 拥有。本文示例中的 `Steve`、`Alex`、世界名和坐标需要替换为实际值；示例时间均相对于执行查询的时刻。

游戏内输入：

```text
/coq
/coq help 1
/coq help 2
/coq help 3
```

三页帮助分别介绍查询入门、筛选与组件、面板与管理。点击帮助里的命令可填入聊天栏，再调整参数。`/coq` 是 `/coreprotectquery` 的别名，`l` 是 `lookup` 的简写。

本文代码块按游戏内命令书写。服务器控制台通常省略开头的 `/`；控制台不支持手持物品 debug、物品面板和 WE 选区，半径查询需显式提供世界与中心坐标。

## 2. 第一次查询

站在需要调查的位置，先查附近一小时的记录：

```text
/coq near t:1h
```

`near` 默认以当前方块坐标为中心，查询 X/Y/Z 各 ±5 的范围。它不是“只查你看着的方块”。未指定 `a:` 时默认合并方块记录（含交互、击杀）、容器记录和物品记录，不会自动包含聊天、命令等所有日志。

如果正在调查建筑被拆，明确限定破坏记录：

```text
/coq l a:-block t:1h r:10
```

这条命令查询当前世界、当前位置 X/Z 各 ±10 范围内的一小时破坏记录，不限制高度。继续缩小到某位玩家和某种方块：

```text
/coq l a:-block u:Steve i:stone t:1h r:10
```

参数顺序可以调整，不同筛选条件一起生效。这条命令表示“Steve 在这段时间和范围内破坏的石头”。每次都需要写出完整查询条件；新查询不会继承上一条查询的玩家或范围。

结果默认从新到旧排列。悬停文字可以查看时间和位置；物品记录可悬停查看还原的物品信息。翻到第二页：

```text
/coq l 2
```

也可以点击结果中的上一页、下一页。

## 3. 参数速查

通用格式：

```text
/coq l a:类型 t:时间 u:玩家 i:包含类型 e:排除对象 r:范围
```

只填写需要的条件；默认配置要求提供 `t:`。以下占位说明不是要原样输入的命令。

| 参数 | 常用写法 | 说明 |
| --- | --- | --- |
| `a:` / `action:` | `a:container` | 记录类型，完整对照见下一张表 |
| `t:` / `time:` | `t:1d2h` | 时间段 |
| `u:` / `user:` / `users:` / `p:` | `u:Steve,Alex` | 玩家列表，任一玩家匹配即可；`p:` 不是页码 |
| `i:` / `include:` | `i:diamond,iron_ingot` | 包含的物品、方块或实体类型，列表内取并集 |
| `e:` / `exclude:` | `e:Alex` | 排除物品、实体或玩家，排除优先 |
| `content:` / `c:` | `content:map_id=101205` | 文字正则或物品组件条件，取决于动作类型 |
| `r:` / `radius:` | `r:10` | 空间范围，见时间与范围章节 |
| `world:` / `w:` | `world:world_nether` | 指定世界 |
| `coord:` / `coords:` | `coord:100,64,-200` | 指定中心坐标；`c:` 始终是内容条件 |
| `page:` | `page:2` | 新查询从第几页开始 |
| `rows:` | `rows:30` | 每页条数，也可写 `page:2:30` |

`i:` 还可写为 `item:`、`items:`、`b:`、`block:`、`blocks:`；`content:` 还可写为 `message:`、`m:`、`command:`。建议日常固定使用上表中的短写，避免混淆。

物品类型接受 `diamond` 和 `minecraft:diamond`。同一个参数不要重复填写：查询两位玩家写 `u:Steve,Alex`，不要写两次 `u:`。`i:` 不要混合实体与物品，例如不要把 `zombie` 与 `diamond` 放在同一列表。`e:` 按物品、实体、玩家的顺序识别名称。

### 动作方向对照

| 动作 | 查询内容 | 正号 / 负号含义 |
| --- | --- | --- |
| `block` | 方块放置与破坏 | `+block` 放置；`-block` 破坏 |
| `click` | 方块交互 | 不使用正负号 |
| `kill` | 击杀记录 | 不使用正负号 |
| `container` | 普通容器存取 | `+container` 放入容器；`-container` 从容器取出 |
| `item` | 物品相关记录 | `+item` 拾取、末影箱取出；`-item` 掉落、末影箱放入、投掷、射出 |
| `inventory` | 按玩家背包方向合并相关记录 | `+inventory` 背包增加；`-inventory` 背包减少；必须指定 `u:` |
| `chat` | 聊天 | 不使用正负号 |
| `command` | 执行命令 | 不使用正负号 |
| `sign` | 非空招牌文字记录 | 不使用正负号 |
| `session` | 登录、退出 | `+session` 登录；`-session` 退出 |
| `username` | 改名记录 | 不使用正负号；不能附带空间条件 |

例如，从普通箱子取出钻石对应 `-container`，从玩家背包方向看则是增加。调查普通箱子应使用 `container`，不要把 `+item` 理解成所有来源的物品增加。`inventory` 展示的是相关历史动作，不是玩家当前背包快照。

省略 `a:` 通常会合并多个来源；如果 `i:` 中全是非方块物品，会自动推断为 `item`。为了确保查到预期来源，教程示例尽量显式填写 `a:`。

## 4. 时间与范围

### 时间怎么写

| 条件 | 含义 |
| --- | --- |
| `t:30m` | 最近 30 分钟 |
| `t:1.5h` | 最近一个半小时 |
| `t:1d2h` | 最近一天两小时 |
| `t:1w` | 最近一周 |
| `t:10d-12d` | 距今 12 天到 10 天之间 |

单位支持 `y/mo/w/d/h/m/s`，其中 `mo` 是月，`m` 是分钟。默认最大时间跨度为 7 天；限制的是区间宽度，所以默认允许 `10d-12d` 这样的两天区间。实际限制以服务器配置为准。

### 附近、指定地点和世界

范围使用各坐标轴的边界，包含边界上的方块，并非球形距离筛选。

| 条件 | 查询范围 |
| --- | --- |
| `r:5` | X/Z 各 ±5，不限制 Y |
| `r:5x3` | X/Z 各 ±5，Y ±3 |
| `r:5x3x8` | X ±5，Y ±3，Z ±8 |
| `r:0x0` | 中心的精确 XYZ 位置 |
| `world:world` | 名为 `world` 的整个世界 |
| `r:#world` | 同上；`world` 是实际世界名，不是“当前世界”占位符 |
| `r:#global` | 不限制世界与坐标，其他条件仍然生效 |

普通半径未指定中心时使用玩家当前位置与当前世界。没有填写任何空间参数的普通 `lookup` 不会自动限制到附近。

查询指定地点附近的箱子存取：

```text
/coq l a:container t:1h world:world coord:100,64,-200 r:5x3
```

精确查询这个坐标的容器记录：

```text
/coq l a:container t:1d world:world coord:100,64,-200 r:0x0
```

只写 `coord:100,64,-200` 而不写半径时，会按 X/Z 精确筛选，不限制高度。需要精确 XYZ 时务必加 `r:0x0`。也支持 `coord:100,-200` 或分写 `x:100 y:64 z:-200`；三维查询建议写完整 XYZ。

控制台可使用上面显式指定世界、坐标的命令。`r:#global` 不能再与 `world:` 或 `coord:` 混用。半径小数会截为整数，建议直接填非负整数。

### WorldEdit / FAWE 选区

先使用服务器已有的 WorldEdit / FAWE 完成选区，再执行：

```text
/coq l a:block t:1d r:#we
```

`r:#worldedit` 与 `r:#we` 等价。选区必须位于玩家当前世界，不能同时附加 `world:` 或 `coord:`。椭球等非长方体选区按外接包围盒查询。缺少依赖或选区不完整时会报错。

查询开始后再移动、换世界或修改选区，不会改变已有查询翻页使用的范围；需要更新范围时重新输入完整查询。

## 5. 按场景调查

### 5.1 谁拆了建筑、谁放了方块

站在现场，分别查破坏和放置：

```text
/coq l a:-block t:1d r:20
/coq l a:+block t:1d r:20
```

只查石头被破坏，并排除 Alex：

```text
/coq l a:-block t:1d r:20 i:stone e:Alex
```

查门类方块的变化：

```text
/coq l a:block t:1d r:20 i:#door
```

支持的 CoreProtect 方块组为 `#button`、`#container`、`#door`、`#natural`、`#pressure_plate`、`#shulker_box`，需要兼容的 CoreProtect 分组接口。`i:#container` 是方块类型组；查询箱内物品存取仍使用 `a:container`。

### 5.2 谁从箱子拿走了钻石

先查附近容器取出记录：

```text
/coq l a:-container i:diamond t:1d r:5x3
```

如果附近有多个箱子，改用目标容器的准确坐标：

```text
/coq l a:-container i:diamond t:1d world:world coord:100,64,-200 r:0x0
```

需要同时查看放入和取出时改为 `a:container`；只查存入则改为 `a:+container`。记录中的玩家是调查线索，按实际时间、动作和数量继续核对。

### 5.3 玩家获得或失去了哪些物品

```text
/coq l a:+inventory u:Steve t:1h
/coq l a:-inventory u:Steve t:1h
/coq l a:inventory u:Steve i:diamond t:1h
```

`inventory` 必须指定玩家。若需要查看拾取、丢弃或末影箱相关物品记录，可以用：

```text
/coq l a:item u:Steve i:diamond t:1h
/coq l a:+item u:Steve i:diamond t:1h
/coq l a:-item u:Steve i:diamond t:1h
```

### 5.4 谁交互过方块、谁击杀了实体

```text
/coq l a:click t:1h r:5x5
/coq l a:kill i:zombie t:1d r:20
/coq l a:kill i:player t:1d r:20
```

`i:player` 筛选被击杀对象为玩家的记录。`u:` 是记录行为者筛选，不应直接当作受害者姓名条件。

### 5.5 查聊天、命令和招牌文字

```text
/coq l a:chat u:Steve t:1d content:"交易"
/coq l a:command u:Steve t:1d content:"^/op .*"
/coq l a:sign t:1d r:20 content:"hello.*world"
```

这些类型的 `content:` 使用数据库正则。`^` 表示开头，`.*` 表示任意长度字符；含空格时用成对引号包住。普通词语可以搜索含该词语的文本，但 `.`、`*` 等正则符号不是普通字面字符。

正则的大小写和支持语法取决于数据库，不能把不同数据库的行为视为完全一致。例如 ClickHouse 使用 RE2，默认区分大小写，不支持前后查找或回溯引用。复杂表达式先在小时间范围内验证。物品组件搜索不使用这里的正则规则。

### 5.6 查登录、退出和改名

```text
/coq l a:session u:Steve t:1d
/coq l a:+session u:Steve t:1d
/coq l a:-session u:Steve t:1d
/coq l a:username u:Steve t:7d
```

改名记录没有位置，不能添加 `r:`、`world:`、`coord:`，也不能通过 `near` 查询改名。

## 6. 自定义物品与组件搜索

组件筛选用于 `item`、`container` 及其正负方向动作。请显式指定动作；混合查询和 `inventory` 不接受组件 `content:` 条件。

### 6.1 先区分四种写法

| 条件 | 匹配含义 |
| --- | --- |
| `content:map_id` | 物品拥有 `minecraft:map_id` 有效组件 |
| `content:map_id=101205` | 该组件的完整值等于 `101205` |
| `content:"minecraft:filled_map"` | 物品类型为已填充地图 |
| `content:"smc:dou_dizhu_table"` | 在配置白名单的组件内递归查找这个完整字符串值 |

组件名可省略 `minecraft:`。已注册的组件名优先作为存在性条件，已注册的物品 ID 优先作为类型条件，其他字符串才进入白名单值搜索。

查带地图编号的物品，再查特定编号：

```text
/coq l a:item t:1d content:map_id
/coq l a:item t:1d content:map_id=101205
```

这里查询的是历史记录还原出的物品，不是管理员当前手里的物品。有效组件包括当前服务器提供的默认值，因此存在某个默认组件不一定能区分自定义道具。

### 6.2 从手持道具找到可用条件

以一个基础材质为 `paper`、自定义标识为 `smc:dou_dizhu_table` 的道具为例：

1. 主手拿着用于参考的道具，执行 `/coq debug item`。
2. 查看组件列表；需要下一页时执行 `/coq debug item 2`。每页 10 个组件，翻页会重新读取当前主手物品。
3. 找到保存标识的组件，例如 `minecraft:custom_data`。可以点击 `[复制值]` 或 `[复制条件]`，复制内容不会因聊天预览省略而截断。
4. 如果要直接按内部字符串标识查找，将该组件加入白名单。

```text
/coq debug whitelist add minecraft:custom_data
```

这一步需要额外的重载权限，也可点击 debug 行中的 `[加入白名单]`。成功后会保存配置并立即生效，无须再重载。

然后执行：

```text
/coq l a:item u:Steve i:paper t:1d content:"smc:dou_dizhu_table"
/coq items
```

如果调查的是普通箱子存取，将 `a:item` 换为 `a:container`。玩家未知时可以去掉 `u:Steve`，优先保留较小的时间范围和基础物品类型。

字符串搜索会递归检查白名单组件中的对象字段值和列表元素。它区分大小写，只匹配完整字符串值，不匹配字段名、子串，也不会把数值自动转成字符串。`content:"dou_dizhu"` 不会命中值 `smc:dou_dizhu_table`。这项功能不限定 CraftEngine 或其他特定道具插件。

### 6.3 复制完整组件条件

如果希望精确匹配某个组件的完整值，使用 debug 的 `[复制条件]`，或在历史物品面板右键物品后点击组件行，将复制内容直接粘贴在 `content:` 后。

例如：

```text
/coq l a:item i:potion t:1h content:{"minecraft:max_stack_size":1}
/coq l a:item i:potion t:1h content:{"minecraft:max_stack_size":1,"minecraft:rarity":"common"}
```

多个组件条件必须全部满足，物品的其他组件不影响匹配。对象字段顺序不影响匹配，列表顺序和 NBT 数字类型影响匹配，例如 `1` 和 `1b` 不相等。`custom_data={...}` 比较的是整个组件值，不表示“只要包含这些字段”。复杂名称、Lore、附魔和自定义数据建议复制，减少转义错误。

显式组件条件不受白名单限制。白名单决定组件 Tab 补全、面板显示的组件以及省略路径的字符串搜索范围。面板最多展示名单前 12 个组件中的有效项；字符串搜索使用整个名单。空名单关闭字符串值搜索，但不关闭显式组件条件。

已有的组合写法也可使用：

```text
/coq l a:item t:1d content:"minecraft:filled_map[map_id=101205]"
```

不要将组件放进 `i:` 或 `e:`。例如 `i:filled_map[map_id=101205]` 会被拒绝，应拆成 `i:filled_map content:map_id=101205`。

### 6.4 搜索未完成时缩小范围

组件查询需要还原候选历史物品。默认最多检查 2000 条候选，查询超时为 5 秒；这些是服务器可调整的限制。

遇到“搜索未完成”，先缩短时间，再补充玩家、物品类型或空间范围。例如：

```text
/coq l a:item u:Steve i:paper t:30m content:"smc:dou_dizhu_table"
```

超限不代表没有匹配物品。历史元数据无法还原时，组件查询也会明确失败，不能将该记录视为不匹配。历史物品按保存的元数据及当前服务器默认组件还原，无法恢复 CoreProtect 未保存的旧版本默认值。

## 7. 历史物品面板

先完成一次 `item` 或 `container` 明细查询，再打开面板：

```text
/coq l a:container i:diamond t:1d r:5x3
/coq items
```

正负方向的物品、容器明细查询同样适用。混合查询、`inventory` 和计数查询不能打开此面板。

| 操作 | 行为 |
| --- | --- |
| 非创造模式左键或右键物品 | 查看记录详情和白名单组件 |
| 创造模式右键物品 | 查看详情 |
| 创造模式左键物品 | 向背包领取历史物品副本，可以重复领取 |
| 点击聊天中的组件行 | 复制完整组件条件 |
| 点击详情中的坐标按钮 | 执行 `/tppos x y z` |
| 面板底部按钮 | 翻页或关闭 |

**创造模式左键会实际添加物品。** 领取数量等于格子显示数量，最多一组；详情显示原始记录数量。历史记录不会被删除或回滚，也不会从其他玩家或容器扣除物品。背包空间不足会提示，无法还原的物品不能领取。Shift、数字键、双击和拖拽不用于取物。

坐标按钮依赖服务器已有的 `/tppos` 命令和权限，命令不包含世界参数；使用前确认所在世界与记录世界一致。

指定页码和每页条数：

```text
/coq items 2
/coq items 2:15
```

面板每页最多 45 条。聊天查询若用了更大页大小，可用 `/coq items 1:45` 调整。每条记录占一个格子，面板仅保留当前页；关闭后释放物品数据，但未过期的查询会话仍可再次使用。

## 8. 翻页与计数

### 继续最近查询

```text
/coq l 2
/coq page 2
/coq l 2:30
```

前两条翻到第二页；第三条将每页条数改成 30 并显示第二页。也支持 `/coq l page:2`。需要新查询直接从第二页开始，可以写：

```text
/coq l a:block t:1h r:20 page:2 rows:30
```

默认每页 15 条，聊天查询最多每页 100 条，可浏览结果上限默认 1000 条，均以服务器配置为准。

每位玩家和控制台分别保存最近查询。新查询会替换旧查询；默认会话有效期 5 分钟，翻页不会续期。翻页保留第一次查询的时间基准与范围，但会重新读取数据库，因此之后补写或清理的记录仍可能影响结果。

### 只统计记录条数

```text
/coq l a:-container i:diamond t:1d r:5x3 #count
```

`#sum` 与 `#count` 在这里都统计记录条数，**不是钻石数量求和**。一次取出一组物品可能对应一条记录，不能把记录数当成物品数量。计数也受结果上限限制，超限提示不代表精确的全库总数。

需要在记录行显示更多定位信息：

```text
/coq l a:block t:1h r:20 #verbose
```

`#verbose` 增加来源、记录 ID 和坐标文本；`#silent` 关闭这部分扩展显示，不会隐藏错误消息。

## 9. 管理命令与权限

| 权限 | 用途 | 默认 |
| --- | --- | --- |
| `coreprotectaddon.command.query` | 查询、帮助、翻页和物品面板 | OP |
| `coreprotectaddon.command.debug` | 查看、复制主手物品组件 | OP |
| `coreprotectaddon.command.reload` | 重载配置和数据库连接；保存白名单修改 | OP |

debug 白名单操作还需具备 debug 入口权限。查看物品组件可用 `/coq debug`，等价于第一页的 `/coq debug item`。移除组件白名单：

```text
/coq debug whitelist remove minecraft:custom_data
```

移除后，该组件不再参与省略路径的字符串搜索和白名单展示，显式组件条件仍可使用。

手动修改 `plugins/CoreProtectAddon/config.yml` 后执行：

```text
/coq reload
```

插件在后台验证配置与数据库连接。成功后清理旧面板、查询会话和任务，需要重新查询；失败则保留原配置与连接。重载或白名单保存正在执行时，重复操作会提示稍候。

`/coq reload` 与 `/co reload` 分别重载 Addon 和 CoreProtect，不能互相代替。

## 10. 常见问题

| 现象 | 原因与处理 |
| --- | --- |
| 提示必须指定时间 | 默认要求 `t:`，补上 `t:1h` 等条件；`near` 也需要时间 |
| 查询没有记录 | 核对动作方向、时间、世界、坐标及数据库目标；确认 CoreProtect 实际保存了该事件；逐项去掉可疑条件并保持较小时间范围 |
| `inventory` 提示缺少玩家 | 添加 `u:Steve`，它必须有玩家条件 |
| `content:` 不适用于当前查询 | 文字筛选使用 `chat/command/sign`；组件筛选使用 `item/container`，不要留在默认混合查询 |
| 面板提示没有适用的最近查询 | 重新执行物品或容器明细查询，随后执行 `/coq items`；中间的新查询会替换会话 |
| 查询已过期或没有最近查询 | 重新输入完整命令，单独翻页不会恢复过期条件 |
| 页码越界或超过结果上限 | 返回已有页，或缩小条件重新查询；不能靠不断翻页绕过结果上限 |
| 面板提示每页条数过多 | 使用 `/coq items 1:45` 或更小页大小 |
| 搜索未完成、超时 | 缩短时间，增加玩家、类型或范围条件；不要把失败当成零结果 |
| 上一条查询仍在执行、系统繁忙 | 等当前任务退出后再试；关闭面板后的取消可能需要等待数据库响应 |
| 历史物品无法还原 | 日志元数据可能损坏、不兼容或过大；普通记录仍可查看，组件搜索遇到此类记录会失败 |
| 字符串道具标识搜不到 | 确认标识所在组件在白名单内、字符串完整且大小写一致，并确认查询的是正确来源 |
| WE 选区报错 | 检查依赖是否启用、选区是否完整且位于当前世界，并去掉额外世界/坐标参数 |
| 点击坐标不能传送 | 检查服务器 `/tppos` 命令及权限；它由现有传送插件处理 |
| 未知命令或参数重复 | 使用 `/coq l a:chat`、`a:command`、`a:item`；没有 `/coq item`，旧 `/coq chat`、`/coq command` 已移除；同类筛选合并成逗号列表 |

不要直接照搬 CoreProtect 的所有参数：这里 `c:` 表示内容，`p:` 表示玩家；不支持回滚参数 `#preview` 或依赖检查器状态的 `u:#container`。

更多配置、兼容边界和实现说明见 [README](../README.md)；范围与多来源查询说明见 [1.6.0 查询文档](LOOKUP_1.6.0.md)。
